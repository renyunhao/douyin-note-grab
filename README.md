# Douyin 图文取图

一个 Chrome / Edge 的 Manifest V3 扩展：按关键词搜索抖音「图文」笔记，收集笔记的原图 URL，导出 JSON 或批量下载图片。

在**你自己已登录的浏览器里手动点一次**运行，不是后台爬虫，也不需要额外起进程。

## 安装

1. 打开 `edge://extensions`（Chrome 是 `chrome://extensions`），开启「开发人员模式」。
2. 点「加载解压缩的扩展」，选择本仓库根目录（`manifest.json` 所在这一层）。
3. 先在浏览器里正常登录 [douyin.com](https://www.douyin.com)。

> 改了代码后要在扩展页点刷新 ↻，并刷新已打开的抖音标签页。

## 使用

点工具栏图标打开侧边栏，填关键词和数量，点「开始收集」。扩展会自动跳转搜索页、点开右上角「筛选 → 内容形式 → 图文」，然后边滚动边截获结果，达到数量即停。

| 控件 | 作用 |
| --- | --- |
| 关键词 / 数量 | `数量` 是**本次新增的硬上限**。抖音一次响应就有约 10 条，超出部分直接丢弃，不会多收 |
| 排序 | 对应筛选面板的「排序依据」：综合排序 / 最新发布 / 最多点赞。选「综合排序」时不点，保持默认 |
| 文件名模板 | 下载后的路径与文件名，见下面「图片命名」。默认 `{desc}_{seq}` |
| 追加模式（默认开） | 开着：保留上次列表，`数量` 表示"再新增 N 条"。关掉：开始即清空列表 |
| 导出 JSON / 下载图片 / 复制图片 URL | 三个独立动作，都基于当前列表 |

## 图片命名

「文件名模板」输入框控制每张图存到哪里、叫什么。输入框下方实时显示按**两条内置示例笔记**渲染出的文件名（`background.js` 里的 `SAMPLE_NOTES`，共 3 张图），不依赖库里的数据，所以刚装好、一条还没收集时也能看到效果。预览走的是和下载同一个 `renderName()`，占位符、补零、清洗规则完全一致，只是数据换成示例。

示例数据是刻意选的：示例 1 标题里带 `/`、昵称里带 emoji，用来演示清洗后的样子；示例 2 的第一张图排在整批第 3 张，所以 `{seq}` 给的是 `003` 而不是重新从 `001` 开始，`{index}` 给的才是 `1`。`{keyword}` 渲染成示例关键词「收纳」。模板会存进 `chrome.storage.local`，下次打开还在；清空输入框则回到默认值（也可点「恢复默认」）。

| 变量 | 取值 |
| --- | --- |
| `{desc}` | 笔记标题前 40 字；**无标题的图文回退成 `{noteId}`**，不会只剩个序号 |
| `{seq}` | 本次下载队列的**全局序号**，从 1 开始、跨笔记连续，同一批里不会重名 |
| `{index}` | 图片在该笔记内的序号，从 1 开始（分目录时用这个，跨笔记会重复） |

两个序号都能指定位数补齐：`{seq:3}` → `001`、`{index:2}` → `01`，上限 9 位；写 `{seq}` 或 `{seq:0}` 就是不补。其余变量不认这个参数（`{desc:5}` 里的 `5` 无效）。

### `{seq}` 的增长规则

编号对象是**图片**，不是笔记。`imageJobs()` 按库列表 `job.order` 的顺序走一遍，每条笔记的 `images` 逐张 `++seq`，所以：

```
笔记A(3图) 笔记B(2图) 笔记C(1图)   →   seq = 1 2 3 | 4 5 | 6
```

- **每次点「下载图片」都从 1 重算**，不是接着上次下载的编号往后加。
- 编号在 `slice(0, maxImages)`（默认上限 2000 张）**之前**算完，所以某张图拿到的编号只取决于它在库里的位置，跟这次实际下没下满 2000 张无关。
- **追加模式只往 `order` 尾部加新笔记**，老笔记的 seq 不动、新笔记从后面接续；所以"跑完新任务再全量重下一遍"不会让已有文件的编号漂移。
- 反过来，「清空」或关掉追加（覆盖模式）会重排 `order`，同一张图可能拿到别的 seq——旧文件不会自动改名，会和新的并存。想要**跨任务也稳定**的唯一名，把 `{noteId}` 写进模板（`{desc}_{noteId}_{index}`），别只靠 `{seq}`。
- 缓存去重命中的笔记根本不进 `order`，不占编号。

同一批文件名的唯一性来源是 `{seq}`；仍然撞车（比如两次任务下同名）时靠浏览器 `uniquify` 加 `(1)`，不会覆盖。
| `{noteId}` | 笔记 `aweme_id`，每条笔记唯一 |
| `{author}` | 作者昵称（可能含 emoji、空格） |
| `{user}` | 作者抖音号 `unique_id`，纯 ASCII，比昵称更适合做目录名；抓不到时回退成昵称 |
| `{keyword}` | 本次任务的搜索关键词 |

- 模板里**有 `/` 就是分目录，没有就是平铺**，`douyin-grab/` 这层根目录可以改掉或直接省掉。
- **不写扩展名就不加**。Chrome 会按图片响应头补真实扩展名，所以抖音现在大量返回的 `webp` 不会被伪装成 `.jpg`；写了 `.png` 等则以你写的为准。
- `{desc}` 单独用一定会撞名（同一条笔记的多张图、以及不同笔记同标题），所以默认后面挂了 `{seq}`。想稳定不重复就带上 `{noteId}`。
- `\ / : * ? " < > | ~`、控制字符、连续分隔符都会被清理，昵称/标题里的 `/` 不会意外多出层级，`..` 会被丢掉。单个片段最长 80 字符。
- 名字仍然撞车时靠浏览器 `uniquify` 加 `(1)`，不会覆盖。
- 旧笔记（这次改动之前收集的）没有 `author_uid`，所以 `{user}` 会退回昵称。

常用写法：

```
{desc}_{seq}                              平铺、带标题、同批不重名（默认）
{desc}_{noteId}_{index}                   平铺、把出处钉死在文件名里、跨批次也不撞
douyin-grab/{author}-{noteId}/{index}.jpg 每人一叠、按笔记分目录
{keyword}/{user}/{desc}-{index}.jpg        按关键词→作者→标题归档
```

## 去重与缓存

`chrome.storage.local` 里存一份**已收集笔记**的 `aweme_id → 时间戳`，跨任务、跨重启生效，上限 5000 条按最早写入淘汰。

- 命中缓存的条目会被跳过，日志写 `跳过已收集 X 条`，所以同关键词重复跑只会翻出新内容。
- 「已收集」是在**收集成功那一刻**记录的，不是下载成功才记。收了没下载就重跑会被当重复，此时点「清空缓存」（二次点击确认）。
- 下载不做判重：同一次任务连点两次「下载图片」会靠浏览器的 `uniquify` 产生 `(1)` 副本。

## 工作原理

- **取数不靠 DOM 类名**。`capture.js` 以 `world: "MAIN"` 注入页面，钩住 `fetch` / `XMLHttpRequest`，直接解析抖音自己发出的 `aweme/v1/web/general/search/single` 响应，从 `data[].aweme_info.images[].url_list` 取原图数组。图文的 `aweme_type` 是 `68`，视频是 `0` 且该字段为空，所以"只收图文"是数据层判定的结果。抖音改版换 class 名不影响取数。
- **交互靠文案匹配**。`content.js` 用元素文案找「筛选」「图文」「最新发布」等节点并派发鼠标事件。抖音改了 UI 文案时，改 `content.js` 里的字符串即可。
- **下载要带 Referer**。抖音图片 CDN 校验来源，下载前 `background.js` 会下一条 `declarativeNetRequest` session rule，把 `referer` 设为 `https://www.douyin.com/`。
- **导出 JSON 用 Blob URL**。`data:` URL 的下载会被 Edge 拦掉，所以 JSON 由侧边栏 `URL.createObjectURL(new Blob(...))` 生成再交给 downloads API。
- 任务状态放在 service worker 里，关掉侧边栏不影响正在跑的任务。

## 限制

- 图片 URL 带签名，**几小时后失效**，收集完尽快下载。
- 依赖已登录会话。抖音对异常行为会返回空结果或弹验证，需要人工在页面上过一次。
- 只在 `www.douyin.com` 的搜索页工作。
- 抓到的图片是他人创作内容，请自行确认使用边界。

## 图标

Chrome 对没有图标的扩展会用兜底磁贴：取 manifest `name` 的首字符画一个色块。所以本扩展以前显示的是 `Douyin Note Image Grabber` 的 **D**，兄弟扩展「抖音逐帧控制」显示 **抖**——那不是设计，是没提供图标。

现在四档图标（`icons/icon{16,32,48,128}.png`）是同一个构图，只按尺寸调细节：

深色圆角磁贴 + 一张白色图文卡片，卡片里用**负空间**挖出下载箭头和一条托盘线；卡片和磁贴边框都偏一道抖音青 `#42D2CB` / 品红 `#FE2C55`，即抖音的色差错位质感。语义是"把一张图文卡片存下来"。

刻意没用汉字：一开始 128 用的是「图」字，但密集笔画在 40px 以下必糊，而实测 Chrome 本地**最大只取到 48**（`chrome://extensions` 详情页也是把 48 放大画的），汉字版等于永远看不到。所以全尺寸统一成卡片+箭头，128 只是同一构图的高保真版（`weight` 更细、色差偏移更大），留给应用商店列表图。

各尺寸的可见位置：工具栏按钮和拼图菜单取 16（高分屏取 32 缩放）、`chrome://extensions` 列表与详情页取 48、128 仅上架时用。

想改样式就编辑 `tools/make-icons.ps1` 里的 `$plans`（每档的色差偏移 `shift`、边框双色 `rimAlpha`、笔画权重 `weight`、`tray` 托盘线开关）和 `$CYAN`/`$PINK`/`$INK`/`$TILE_*` 配色，然后重跑：

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make-icons.ps1
```

脚本只用 Windows 自带的 GDI+（`System.Drawing`），无第三方依赖：先画 512 矢量母版（圆角路径 + 画笔描边，圆头线帽），再用 `HighQualityBicubic` 缩到目标尺寸，所以小图是矢量渲染后降采样、不是位图硬缩放。改完要在 `chrome://extensions` 重装才会换图标（和后台脚本同一个坑）。

## 文件

```
manifest.json     MV3 清单，声明 MAIN / ISOLATED 两个 content script
capture.js        MAIN world：钩 fetch/XHR，解析搜索响应里的图文数组
content.js        ISOLATED world：点筛选、滚动加载、转发数据
background.js     service worker：任务状态、去重缓存、下载命名、导出
sidepanel.*       侧边栏界面
icons/            扩展图标，由 tools/make-icons.ps1 生成
tools/            出图脚本
```

## JSON 输出格式

```json
{
  "keyword": "收纳",
  "exported_at": "2026-10-20T04:00:00.000Z",
  "notes": [
    {
      "aweme_id": "7668522522060524854",
      "aweme_type": 68,
      "desc": "标题文本",
      "author": "作者昵称",
      "author_uid": "作者抖音号",
      "create_time": 1760000000,
      "digg": 1234,
      "page_url": "https://www.douyin.com/note/7668522522060524854",
      "images": ["https://p3-sign.douyinpic.com/..."],
      "images_all": [["原图多镜像地址", "..."]]
    }
  ]
}
```

`images` 是每张图的首选地址（下载用的就是它），`images_all` 保留每张图的全部镜像。
